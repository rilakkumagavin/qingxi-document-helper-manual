01 / 快速開始

第一次使用，先完成這 4 件事

  1. 取得完整 0.9.9 安裝包

    將 Qingxi-0.9.9-windows-x64.zip 完整解壓縮。不要直接在壓縮檔內執行安裝。

  2. 安裝本機助手

    執行「安裝.cmd」，保留 extension、helper、runtime、converter、installer 等資料夾。

  3. 載入瀏覽器外掛

    在 Chrome 或 Edge 擴充功能管理頁開啟開發人員模式，載入安裝後的 extension 資料夾。

  4. 選位置，開始存檔

    登入公文系統，開啟來文，選擇自己的存檔根資料夾，再按「一鍵存檔」。

已安裝舊版？請先儲存正在編輯的擬辦，執行新版安裝，再重新載入外掛與公文頁。

02 / 安裝與更新

從完整解壓，到看見 v0.9.9

使用環境

Windows 10／11 x64，搭配 Chrome 或 Edge。需可登入桃園市公文系統。安裝包約 509 MB，建議預留至少 2 GB 空間。

內含離線元件

Python、pypdf 與 LibreOffice。無須另裝 Microsoft Office；公文系統登入與下載仍需要網路。

  1. 完整解壓 ZIP，雙擊「安裝.cmd」。依安裝畫面完成。
  2. 開啟 chrome://extensions 或 edge://extensions。
  3. 開啟「開發人員模式」，按「載入未封裝項目」。
  4. 選取以下安裝路徑。可先貼到檔案總管位址列，再複製展開後的完整路徑。
%LOCALAPPDATA%\QingxiDocumentHelper\extension

回到公文頁重新整理，面板應顯示 公文助手 v0.9.9。如果看不到面板，確認已開啟含來文正文的頁面。

更新已安裝的電腦

執行新版「安裝.cmd」，到擴充功能管理頁按「重新載入」，再重新整理公文頁。原存檔根資料夾設定會保留。不要同時啟動多套舊助手。

啟動、修復與解除

開始功能表 → 公文助手，可選啟動助手、修復助手或解除安裝。缺少元件時，完整解壓原安裝包並執行「修復.cmd」。解除安裝不刪除已下載的公文；瀏覽器外掛需另行移除。

03 / 一鍵存檔

把本文、附件與公告 HTML 放在一起

  1. 開啟來文並展開文稿總管

    確認右側可看到「本文pdf」及各附件。已有擬辦的分割畫面也可使用。

  2. 設定公文存檔根資料夾

    按「選擇根資料夾」，或填入完整 Windows 路徑後按「套用路徑」。例如 D:\公文存檔。每份公文會另建子資料夾。

  3. 按「一鍵存檔」

    等候本文及附件處理完成，期間保持頁面開啟。不要連續重複點擊。

  4. 核對結果與實際檔案

    例如「本文 PDF：1/1；附件：3/3」表示這次三份附件均回報存檔成功。再開啟資料夾確認本文原檔、附件與 HTML。

04 / 擬辦與併案

同一案件，也能分辨每一組來源

已填擬辦的畫面

在上方來文區使用助手即可。外掛會排除與「本文pdf」重複的快捷提示，不將它誤認為另一份本文。存檔功能不代替系統的儲存、傳送或簽核；重新整理前請先儲存擬辦。

多份來文或併案

展開文稿總管每一組來文／併辦／併案，讓本文與附件節點完整呈現，再按「一鍵存檔」。依每組來源逐一下載，檔名加上來源、組序與文號，避免相同文號或附件編號互相混淆。

來文1_範例文號_本文原檔.pdf
併辦2_範例文號_本文原檔.pdf
併辦2_範例文號_附件1_補充說明.pdf

若兩組各有一份本文及附件，應核對「本文 PDF：2/2；附件：2/2」。若數量不符，先看失敗訊息，確認各組已展開。

05 / 中文命名與轉檔

讀取內容，保留可辨識的檔名

助手在本機嘗試讀取附件內容，依標題命名，保留附件編號與可辨識的併案來源。它採規則式辨識，不會將附件交給 AI，也不能保證每份標題都正確。

各類附件的處理方式
附件處理方式需核對
文字型 PDF讀取文字、辨識標題標題是否完整，是否誤取內文
Word：DOC／DOCX保留原檔，背景產生 ODT 與 PDF表格、字型、圖片與分頁
Excel：XLS／XLSX保留原檔，背景產生 ODS 與 PDF工作表、公式、列印範圍
舊式 Office轉檔後可用本次 PDF 再辨識，整組更名等待轉檔完成再核對名稱
OpenDocument／PPTX／純文字嘗試讀取可辨識的文字標題不代表都有自動轉檔功能
掃描圖像、加密或不可讀檔保留原檔，記錄原因目前沒有 OCR；必要時人工命名

下載時無法判定檔案類型的併案附件，可能暫以 .bin 保存；不應只靠改副檔名認定檔案類型。

為什麼要等轉檔結果？

本文與附件先保存，Office 轉換在背景執行。完成後可看到 ODT／ODS、PDF 及結果文字檔。遇到同名輸出會以流水號區分；重複下載後應人工確認需要保留的版本。

06 / 公告 HTML

從公文正文整理公告草稿

「產生公告 HTML」會顯示可複製的 HTML 原始碼；「一鍵存檔」也會保存 HTML 並顯示結果。通常從主旨開始，整理說明、段落與清單，排除正副本等收件資訊。

  1. 按「產生公告 HTML」，核對主旨、說明、連結及完整性。
  2. 按「複製 HTML」，到校網編輯器切換 HTML／原始碼模式後貼上。
  3. 補齊公告標題、附件連結及必要說明。
  4. 預覽並人工確認權限、個人資料、連結與閱讀順序，再依校內流程發布。
檔名中的「無障礙」是輸出名稱，不代表通過無障礙認證。HTML 與標記 PDF 均仍需人工檢查。

選用 Monica

「開 Monica 處理」是獨立選用流程：整理並複製正文，開啟指定頁面；由使用者登入、貼上並送出。回覆取回後仍需核對。使用者送出內容時會交給 Monica，請遵守校內資料使用規範。

07 / 常見問題

先看訊息，再找對應處理方式

面板版本沒有更新，仍顯示舊版

先儲存擬辦，執行新版安裝.cmd，再於擴充功能管理頁重新載入，最後重新整理公文頁。只更新檔案或只整理頁面都可能尚未套用完整更新。

本文 PDF 是 0/1，但公告 HTML 已出現

HTML 不能代替原始本文。確認文稿總管已展開本文pdf，查看失敗原因，更新外掛後再試。分割畫面與併案請使用最新版。

附件有下載，但名稱仍是 ATTACH

若為 Word／Excel，先等待背景轉檔並查看結果文字檔。若文字不可讀、加密或無可靠標題，會保留原名。即使中文命名成功，也應核對是否為真正標題。

資料夾仍顯示舊名稱

按 F5 更新檔案總管，核對完整存檔路徑。PDF 閱讀器或預覽可能鎖住檔案；關閉該文件後再重試。不要將測試資料夾與正式存檔位置混淆。

本機助手連不上，或無法選資料夾

開始功能表 → 公文助手 → 啟動助手。仍無效時使用完整安裝包執行修復.cmd。避免同時執行多套助手；若選取視窗已開啟，先完成或取消該視窗。

Office 轉檔失敗或一直等待

查看「_轉檔結果.txt」。確認完整 converter 元件存在，檔案沒有密碼，並等候背景處理。複雜排版或不支援格式可能失敗；原檔仍保留。

兩組併案只存了一組

展開每組來源，確認各組本文與附件節點都在，使用新版外掛後重試。核對分母是否符合實際附件數，不以「公告 HTML 已出現」當作全部成功。

要提供哪些資訊協助排錯？

提供面板版本、失敗訊息、預期與實際附件數、檔案格式及轉檔結果。遮蔽個資、簽核內容、登入資料；helper.log 可能含完整本機路徑，不宜直接公開。

08 / 作品與應用

讓重複的存檔工作，變成可核對的流程

實際問題

公文本文與多份附件需反覆下載，原始檔名難以辨識；Office 格式轉換與公告整理需要額外步驟。

解決方式

將公文頁外掛、本機存檔助手與離線轉檔工具串接，讓下載、整理、命名及格式轉換接續執行。

使用價值

目標是減少重複點擊與人工整理，讓承辦人依數量和轉檔結果核對。尚未宣稱經正式研究證實的節省時間或正確率。

資料如何流動

公文系統
本文與附件→瀏覽器外掛
擷取與下載→本機助手
存檔、命名、轉檔→指定資料夾
人工核對

命名及 Office 轉檔於本機執行。此手冊是靜態網站，不讀取公文、不要求登入，也不代替公文系統辦理簽核。

建議展示順序

  1. 使用虛構或已去識別化的公文示例介紹使用情境。
  2. 展示根資料夾設定與一鍵存檔。
  3. 對照本文與附件計數、資料夾結構及中文檔名。
  4. 展示 Office 原檔、開放格式與 PDF，說明核對步驟。
  5. 展示公告 HTML 與功能限制，說明人工審核角色。
